# Grammar examples

Worked, runnable demonstrations of the Screengrid **declarative grammar** —
`validateSpec` and `compileSpec` (grammar spec version `0.2.0`) — driving real
maps. Every example follows the authoring workflow from
[`AGENTS.md`](../../AGENTS.md):

```text
profile the data → declare intent → write the spec → validate → compile → render
```

All data is **synthetic** (seeded, reproducible) but shaped like Greater London,
generated by [`../data/london.js`](../data/london.js). No real or proprietary
data is committed; the same `(count, seed)` always produces the same points.

## Run

From the repo root:

```bash
npm start
# then open http://localhost:8000/examples/grammar/01-density.html
```

(An HTTP server is required — the pages use ES-module imports.)

## The three examples

| File | Grammar features it shows |
| --- | --- |
| [`01-density.html`](01-density.html) | The whole pipeline end to end; a live validation report (errors vs cartographic warnings); `checkability`. |
| [`02-suitability-mcda.html`](02-suitability-mcda.html) | A `derived` **weighted-sum** measure; declared **parameters** with domains, driven by sliders and clamped on compile; global vs local normalization and the comparability warning firing live. |
| [`03-composition.html`](03-composition.html) | `composition` intent; pie glyphs drawn from each cell's lazy `measures` distribution; the category-count guardrail; a sparse-cell reliability cue. |

## The two halves of a compiled layer

`compileSpec` returns only the **analytical** half of a layer —
`aggregationMode`, `cellSizePixels`, `normalizationFunction`,
`aggregationFunction`, `getPosition`, `getWeight` — because the library core is
deliberately domain- and style-agnostic. The **visual** half (a colour ramp for
the palette, an `onDrawCell` callback for the glyph type) is supplied by the
application. [`grammar-render-bridge.js`](grammar-render-bridge.js) is that seam,
shared across the examples:

```js
const report = validateSpec(spec);
if (!report.valid) throw new Error(report.errors.join('\n'));
report.warnings.forEach((w) => console.warn('[cartographic]', w));

const { layerOptions } = compileSpec(spec, { parameters: { w_access: 0.7 } });
map.addLayer(ScreenGridLayerGL.density({
  id: 'grid', data,
  ...layerOptions,                                   // analytical half
  colorScale: colorScaleFromPalette(spec.glyph.palette), // visual half
}));
```

## Verify without a browser

[`smoke-test.mjs`](smoke-test.mjs) drives the data module, the profiler, and
every example spec through validate → compile → execute (including running the
compiled MCDA aggregation and asserting the weights move the score). It is not
part of `npm test`; run it directly:

```bash
node examples/grammar/smoke-test.mjs
```

## Stress test

[`../stress-test/london-stress.html`](../stress-test/london-stress.html) scales
the same generator to **500k** points, toggles square/hex tessellation, and
switches between colour and glyph rendering so the FPS meter exposes the cost the
lazy semantic-cell model defers until a cell is actually read.
